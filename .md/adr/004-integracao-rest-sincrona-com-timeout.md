# ADR-004 — Cliente REST: THTTPClient + System.JSON, síncrono com timeout, tolerante ao contrato v1.0

- Status: Accepted (DEC-04/DEC-14 adotadas, com ajuste)
- Contexto: contrato v1.0 vigente; v1.1 (formato de erro, 4xx/409/422, idempotência) é só proposta, não confirmada pelo C#.
- Alternativas: TIdHTTP (dependência de OpenSSL para HTTPS); TRESTClient (componentes extras, pouco controle); thread/TTask (risco de concorrência VCL/FireDAC).
- Decisão: `System.Net.HttpClient.THTTPClient` + `System.JSON`, dentro de `TFinanceiroClient` (implementa `IFinanceiroGateway`). Chamada síncrona com `ConnectionTimeout`/`ResponseTimeout` do INI (padrão 10 s), cursor de espera e botões desabilitados durante a chamada (evita duplo clique). Números serializados com `TFormatSettings` invariante (ponto decimal), UTF-8, ISO 8601. O gateway devolve um resultado tipado `TResultadoFinanceiro` com categoria: `Sucesso`, `Recusado` (4xx), `Indisponivel` (5xx/timeout/rede), `RespostaInvalida`. Regras de classificação: 200 = sucesso; qualquer 4xx = recusa (mensagem lida de `mensagem` do corpo se existir, senão texto genérico + código HTTP); 5xx/timeout/exceção de rede = indisponível. O cliente **não depende** de campos da v1.1: se o corpo de erro não existir, funciona igual. Header `X-Api-Key` opcional lido do INI (vazio = não envia).
- Consequências: (+) sem DLL/terceiros; UI congela até 10 s no pior caso (aceito, DEC-14; cursor de espera + mensagem "Aguardando Financeiro..."); (-) 409 na quitação (se C3 idempotência não for confirmada) é tratado como recusa; risco registrado no SDD (R-03).
